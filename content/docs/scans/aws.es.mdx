# AWS scanning

Runtz ejecuta 18 comprobaciones de solo lectura en IAM, S3, EC2/EBS, RDS,
CloudTrail y EKS. En **Cloud → Add cloud → Amazon Web Services**, elige
**Connect through the site** o **Scan with Runtz CLI**. Las nuevas conexiones
utilizan una access key de un usuario IAM dedicado. El onboarding con IAM role
queda para una próxima versión; las conexiones existentes siguen disponibles.

## Preparar acceso desde la consola

1. En **IAM → Users → Create user**, crea un usuario dedicado sin acceso a la consola.
2. Descarga la [política de solo lectura](/docs/assets/runtz-aws-readonly-policy.json).
3. En **Permissions → Add permissions → Create inline policy → JSON**, pega la
   política y guárdala como `RuntzReadOnly`.
4. En **Security credentials → Create access key**, selecciona el caso de uso
   correspondiente al lugar donde ejecutas Runtz. Guarda el access key ID y el secret.
5. Copia el account ID de 12 dígitos y elige las regiones que quieres analizar.

## Preparar acceso con AWS CLI

Usa una identidad administrativa autorizada para crear usuarios y políticas.
Confirma el account ID devuelto. Guarda la política como `runtz-readonly-policy.json`
en el directorio actual. Si el nombre del usuario existe, elige un nombre dedicado único.

```bash
aws sts get-caller-identity
aws iam create-user --user-name runtz-security
aws iam put-user-policy --user-name runtz-security --policy-name RuntzReadOnly --policy-document file://runtz-readonly-policy.json
aws iam create-access-key --user-name runtz-security
```

Estos comandos preparan el acceso; el scanner solo lee configuración. Consulta la
[referencia oficial de AWS](https://docs.aws.amazon.com/cli/latest/reference/iam/create-access-key.html).

## Conectar desde el sitio

Selecciona workspace, account ID y regiones. Introduce ambas claves, verifica el
acceso y nombra la conexión. El servicio Security cifra las claves. Las claves root
y las credenciales temporales no son compatibles. El primer scan comienza al
conectar y los siguientes se repiten cada 12 horas.

## Scan with Runtz CLI

[Instala la CLI](/docs/install-cli), inicia sesión con un token del workspace de
destino y ejecuta:

```bash
runtz login
runtz aws config
runtz aws
```

El asistente solicita account ID, access key ID, secret access key, regiones y nombre.
El secret se oculta al escribir y el acceso se verifica antes de guardar. En Linux,
la configuración queda en `~/.config/runtz/config.json`, con acceso exclusivo del
usuario. macOS y Windows utilizan su directorio nativo. `RUNTZ_CONFIG_DIR` permite
cambiarlo.

La configuración se guarda en tu máquina. La CLI envía las credenciales por
HTTPS a Runtz Security para validar el acceso y ejecutar los checks privados.
Esta API solo utiliza las credenciales durante la solicitud, sin guardarlas.
Después, la CLI envía checks, findings y cobertura al workspace.
La primera ejecución interactiva de `runtz aws` abre la configuración y continúa
con el scan. `runtz aws config` solo configura y valida.

Para CI, proporciona `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` y `RUNTZ_TOKEN`
mediante tu gestor de secretos:

```bash
runtz aws --account-id YOUR_ACCOUNT_ID --regions us-east-1,sa-east-1 --high-threshold 1
```

El terminal muestra progreso, resumen y enlace a los resultados. Los umbrales se
evalúan después del envío y devuelven código `3` al alcanzarse. Los resultados se
muestran en **Cloud → Amazon Web Services** con origen CLI. Ejecuta de nuevo o
programa el comando en CI; no hay programación automática en los servidores Runtz.
Desconecta una cuenta vinculada desde el sitio antes de cambiar al modo CLI.

## Cobertura y gestión

Los checks globales se ejecutan una vez; los regionales cubren las regiones elegidas.
Los permisos ausentes y campos sin evaluar aparecen en **Checks**, nunca como
aprobaciones. Un scan fallido conserva los resultados anteriores.

Actualiza las claves locales con `runtz aws config`; en el sitio usa **Settings →
Cloud → Replace access key**. Después de verificar el acceso, revoca la clave
anterior en AWS. Eliminar la conexión Runtz no elimina el usuario IAM ni sus claves.
