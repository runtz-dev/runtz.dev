# AWS scanning

A Runtz executa 18 verificações somente leitura em IAM, S3, EC2/EBS, RDS,
CloudTrail e EKS. Em **Cloud → Add cloud → Amazon Web Services**, escolha
**Connect through the site** ou **Scan with Runtz CLI**. Nesta versão, novas
conexões usam access key de um usuário IAM dedicado. IAM role fica para uma
próxima entrega; conexões existentes continuam acessíveis.

## Preparar acesso pelo console

1. Abra **IAM → Users → Create user** e crie um usuário dedicado, sem acesso ao console.
2. Baixe a [política somente leitura](/docs/assets/runtz-aws-readonly-policy.json).
3. Em **Permissions → Add permissions → Create inline policy → JSON**, cole a
   política e salve como `RuntzReadOnly`.
4. Em **Security credentials → Create access key**, escolha o caso de uso
   correspondente ao local de execução. Guarde o access key ID e o secret access key.
5. Copie o account ID de 12 dígitos e escolha as regiões que serão analisadas.

## Preparar acesso pela AWS CLI

Use uma identidade administrativa autorizada a criar o usuário e a política.
Confira o account ID retornado. Salve a política como `runtz-readonly-policy.json`
na pasta atual. Se o nome do usuário já existir, escolha um nome dedicado único.

```bash
aws sts get-caller-identity
aws iam create-user --user-name runtz-security
aws iam put-user-policy --user-name runtz-security --policy-name RuntzReadOnly --policy-document file://runtz-readonly-policy.json
aws iam create-access-key --user-name runtz-security
```

Esses comandos preparam o acesso. O scanner somente lê configurações. Veja a
[referência oficial da AWS](https://docs.aws.amazon.com/cli/latest/reference/iam/create-access-key.html).

## Conectar pelo site

Selecione workspace, account ID e regiões, informe as duas chaves, verifique o
acesso e nomeie a conexão. As chaves são armazenadas criptografadas no serviço
Security. Chaves root e credenciais temporárias não são aceitas. O primeiro scan
começa ao conectar; os próximos rodam automaticamente a cada 12 horas.

## Scan with Runtz CLI

[Instale a CLI](/docs/install-cli), entre com um token do workspace de destino,
configure e execute:

```bash
runtz login
runtz aws config
runtz aws
```

O assistente pede account ID, access key ID, secret access key, regiões e nome.
O secret fica oculto durante a digitação. A configuração é validada antes de ser
salva em `~/.config/runtz/config.json` no Linux, com acesso restrito ao usuário.
macOS e Windows usam o diretório de configuração nativo. `RUNTZ_CONFIG_DIR`
permite escolher outro diretório.

A configuração é salva na máquina. A CLI envia as credenciais por HTTPS ao
Runtz Security para validar o acesso e executar os checks privados. Essa API
usa as credenciais apenas durante a requisição, sem armazená-las. Depois,
a CLI envia checks, findings e cobertura ao workspace.
Na primeira execução interativa, `runtz aws` abre a configuração automaticamente e
continua para o scan. `runtz aws config` apenas configura e valida.

Para CI, forneça `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` e `RUNTZ_TOKEN`
pelo gerenciador de secrets:

```bash
runtz aws --account-id YOUR_ACCOUNT_ID --regions us-east-1,sa-east-1 --high-threshold 1
```

O terminal mostra progresso, resumo e link dos resultados. O limite de severidade
é avaliado após o envio e retorna código `3` quando atingido. Os resultados aparecem
em **Cloud → Amazon Web Services**, com origem CLI. Execute novamente ou agende no
CI para atualizar; scans CLI não têm agendamento automático no servidor.
Desconecte uma conta vinculada pelo site antes de trocar para CLI.

## Cobertura e gerenciamento

Checks globais rodam uma vez; checks regionais cobrem somente as regiões escolhidas.
Permissões ausentes e campos não avaliados aparecem em **Checks**, nunca como aprovação.
Um scan que falha preserva os resultados anteriores. Revise evidências e limitações
antes de concluir que os recursos estão seguros.

Atualize as chaves locais com `runtz aws config`; no site use **Settings → Cloud →
Replace access key**. Após verificar o acesso, revogue a chave antiga na AWS.
Remover uma conexão na Runtz não exclui o usuário IAM nem revoga suas chaves.
